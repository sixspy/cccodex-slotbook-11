# 关盘拒占说明

锁死日期：2026-11-21（当日钉死，当日锁死）
状态：**已锁死**。改动本说明须先附失败测，再走评审。

## 背景与根因

档期已关盘，前台仍能新占位，关盘标记与实写对不上。
根因：关盘（`POST /api/slots/close`）只改 `slots.status`，不拦占位写口——
候补晋升 `POST /api/waitlist/promote` 未读档期态即落 `占位中` 新行。

## 钉死口径：甲路径 · 关盘校验整笔回滚

本仓正确性口径**只走甲路径**，乙路径（关盘核销影子切换）**禁用，两边不得混用**：

- 两个占位写口（`POST /api/holds`、`POST /api/waitlist/promote`）在档锁
  `slot:{code}` 内、任何业务写之前读档期态；
- 读到已关盘 → **占位零增、整笔回滚**（拒占点之前不得触碰 holds/waitlist/bookings），
  只把拒占痕（`audit_trail.action='hold_reject_closed'`）提交落库，再以 409
  「档期已关盘，禁止占位」拒写；
- 拒占痕落库失败则拒写与回滚同败，不留半截；
- 本仓不落任何关盘核销影子表/影子行；发现即视为偏航。

实现锚点：`backend/hold_svc.py::reject_closed_hold`（两写口共用同一拒占函数，
`backend/waitlist_svc.py` 晋升路径同口径调用）。

## 争用口径

两人同时对已关档占位，须抢档锁 `slot:{code}`；后到者只留争用痕
（`contention_log`，先于拒写提交落库，不得随回滚吞掉），不写任何业务行。
锚点：`backend/locks.py::require_lock`。

## 五处同态

关盘态（`slots.status`）、占位结果（`holds`）、余席（`capacity-booked-占位中`）、
对账（`/api/reconcile*`）、审计（`/api/audit`）同读一源：

- 拒占后：态仍关闭、占位零增、余席不动、对账通过、审计有拒占痕；
- 对账把「已关档仍挂占位中」判异常（`ok=False`），用于写口失守的兜底发现。
  锚点：`backend/reconcile_svc.py`。

## 偏航处理

任何偏离本口径的实现（含引入影子写、绕开档锁直写、只改前端）视为
**关盘拒占偏航**：记审计并拒写，按本说明回正。

## 明确禁止

- 禁止只灰掉开档钮充当修复（前端置灰不是拒占，必须服务端写口拒写）；
- 禁止跳过失败测直线改实现；禁止无测直线改文案。
